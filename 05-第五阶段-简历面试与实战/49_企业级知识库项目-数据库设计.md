# 49. 企业级知识库项目：PostgreSQL + MongoDB 的文档模块数据库设计

> 阶段：第五阶段 | 前置知识：PostgreSQL 基础、数据库设计

## 设计目标

企业级知识库系统需要存储：
- 文档元数据（名称、类型、大小、上传者、状态）
- 文档内容（解析后的纯文本、分块数据）
- 向量索引（用 PGVector 或专用向量库）
- 用户信息、权限、操作日志

**选型**：PostgreSQL 存结构化数据（文档元数据、用户、权限），MongoDB 存灵活的文档内容和分块数据（JSON 结构灵活）。

## PostgreSQL 表设计

### 1. 用户表（users）
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) DEFAULT 'user',  -- admin / user / viewer
    avatar_url VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 2. 文档表（documents）
```sql
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_type VARCHAR(20) NOT NULL,  -- pdf / docx / xlsx / pptx / txt / md
    file_size BIGINT NOT NULL,
    file_url VARCHAR(500) NOT NULL,  -- OSS/MinIO 存储地址
    status VARCHAR(20) DEFAULT 'pending',  -- pending/parsing/parsed/failed
    chunk_count INT DEFAULT 0,
    uploader_id INT REFERENCES users(id),
    category_id INT REFERENCES categories(id),
    tags TEXT[],  -- PostgreSQL 数组类型
    is_public BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_documents_status ON documents(status);
CREATE INDEX idx_documents_uploader ON documents(uploader_id);
CREATE INDEX idx_documents_category ON documents(category_id);
```

### 3. 文档分类表（categories）
```sql
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    parent_id INT REFERENCES categories(id),  -- 支持多级分类
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 4. 文档审核表（document_reviews）
```sql
CREATE TABLE document_reviews (
    id SERIAL PRIMARY KEY,
    document_id INT REFERENCES documents(id),
    reviewer_id INT REFERENCES users(id),
    status VARCHAR(20) NOT NULL,  -- pending/approved/rejected
    comment TEXT,
    reviewed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 5. 对话历史表（conversations）
```sql
CREATE TABLE conversations (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id),
    title VARCHAR(200),
    document_ids INT[],  -- 关联的文档ID数组
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE messages (
    id SERIAL PRIMARY KEY,
    conversation_id INT REFERENCES conversations(id),
    role VARCHAR(20) NOT NULL,  -- user / assistant
    content TEXT NOT NULL,
    sources JSONB,  -- 引用的文档片段
    token_usage JSONB,  -- token 消耗统计
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_messages_conversation ON messages(conversation_id);
```

### 6. 向量存储（PGVector 方案）
```sql
-- 启用 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE document_chunks (
    id SERIAL PRIMARY KEY,
    document_id INT REFERENCES documents(id),
    chunk_index INT NOT NULL,
    content TEXT NOT NULL,
    embedding vector(1536),  -- text-embedding-3-small 维度
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX ON document_chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
CREATE INDEX idx_chunks_document ON document_chunks(document_id);
```

## MongoDB 集合设计

### 1. 文档原始内容（document_contents）
```javascript
// MongoDB 集合：document_contents
{
  _id: ObjectId,
  document_id: 123,  // 关联 PostgreSQL documents.id
  raw_text: "完整的文档纯文本...",
  structure: {
    // 文档结构：标题、段落、表格、图片
    type: "doc",
    content: [
      { type: "heading", level: 1, text: "第一章" },
      { type: "paragraph", text: "..." },
      { type: "table", rows: [...] }
    ]
  },
  parsed_at: ISODate
}
```

### 2. 文档分块详情（chunk_details）
```javascript
// MongoDB 集合：chunk_details
{
  _id: ObjectId,
  document_id: 123,
  chunk_id: 456,  // 关联 PostgreSQL document_chunks.id
  content: "分块文本内容...",
  metadata: {
    page: 5,
    section: "第三章 第二节",
    char_start: 1200,
    char_end: 1700,
    has_table: false,
    has_image: true
  },
  tokens: 150
}
```

## 为什么 PostgreSQL + MongoDB？

| 数据类型 | 存储 | 原因 |
|----------|------|------|
| 用户、文档元数据、权限、日志 | PostgreSQL | 结构化、需要事务、关系查询 |
| 文档原始内容、分块详情 | MongoDB | 结构灵活、JSON 嵌套、大文本 |
| 向量索引 | PGVector 或 Milvus | 向量检索专用 |
| 缓存、会话 | Redis | 高性能 KV |

**简化方案**：小项目可以只用 PostgreSQL（JSONB 存灵活数据 + PGVector 存向量），不用 MongoDB。

## Python 操作示例

```python
# SQLAlchemy 模型示例
from sqlalchemy import create_engine, Column, Integer, String, Text, BigInteger, Boolean, DateTime, ARRAY
from sqlalchemy.ext.declarative import declarative_base
from datetime import datetime

Base = declarative_base()

class Document(Base):
    __tablename__ = 'documents'
    id = Column(Integer, primary_key=True)
    title = Column(String(200), nullable=False)
    file_name = Column(String(255), nullable=False)
    file_type = Column(String(20), nullable=False)
    file_size = Column(BigInteger, nullable=False)
    file_url = Column(String(500), nullable=False)
    status = Column(String(20), default='pending')
    chunk_count = Column(Integer, default=0)
    uploader_id = Column(Integer)
    tags = Column(ARRAY(String))
    is_public = Column(Boolean, default=False)
    created_at = Column(DateTime, default=datetime.now)
    updated_at = Column(DateTime, default=datetime.now, onupdate=datetime.now)

# 使用
engine = create_engine('postgresql://user:password@localhost:5432/knowledge_base')
Base.metadata.create_all(engine)
```

## 学习要点

1. 企业级知识库用 PostgreSQL 存结构化数据，MongoDB 存灵活的文档内容
2. 小项目可以只用 PostgreSQL（JSONB + PGVector），减少维护成本
3. 文档状态机设计很重要：pending→parsing→parsed→failed，审核状态独立
4. 向量存储可以用 PGVector（简单）或 Milvus（大规模）
5. 对话历史和消息分开存储，消息表用 sources 字段记录引用来源
